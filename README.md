# FinGuard · Financial Transaction Anomaly Detection & Investigation Platform

A full-stack financial transaction monitoring, risk evaluation, and fraud investigation platform built with FastAPI and Next.js (App Router, Tailwind CSS).

---

## Architecture & Team Division

To maintain clean separation of concerns and avoid Git merge conflicts, the frontend is divided into two distinct ownership domains:

| Module / Scope | Path | Owner | Description |
|---|---|---|---|
| **App Shell & Layout** | `frontend/app/layout.jsx`, `frontend/app/globals.css`, `frontend/components/layout/` | Developer 1 | Persistent desktop sidebar, mobile responsive drawer & header, TopBar controls, and design system. |
| **Main Dashboard** | `frontend/app/page.jsx` | Developer 1 | Portfolio surveillance overview, KPI metric cards, 7-day volume vs. anomaly trends, risk distribution, and review queue. |
| **Transactions Module** | `frontend/app/transactions/**` | Developer 1 | Searchable transaction ledger, multi-filter bar, pagination, simulation modal, and dedicated deep-dive route (`[id]`). |
| **Shared UI Primitives** | `frontend/components/ui/**` | Developer 1 | Reusable primitives (`StatCard`, `StatusBadge`, `DataTable`, `FilterBar`, `Modal`, `RiskGauge`). |
| **API Client & Offline Mock** | `frontend/lib/api.js` | Developer 1 | Resilient API client with seamless offline fallback data for independent frontend development. |
| **Alerts Route** | `frontend/app/alerts/page.jsx` | Developer 2 | Triage and status progression for security alerts generated by the detection engine. |
| **Investigation Cases** | `frontend/app/cases/page.jsx` | Developer 2 | Case management, analyst assignment, outcome recording, and investigation audit notes. |

## Key Frontend Features

### 1. Main Dashboard (`/`)
* **Surveillance KPIs**: Total Monitored Volume (₹), Total Transactions Analyzed, Flagged Anomalies, and Active Alerts & Cases.
* **7-Day Trend Chart**: Dual-bar comparison of regular transaction volume against flagged anomaly spikes.
* **Risk Tier Distribution**: Breakdown of current transactions across Critical (85+), High (70–84), Medium (40–69), and Low (<40) tiers.
* **Top-Priority Review Queue**: Instant preview of high-risk transactions with direct links to forensic deep-dives.
* **Instant Detection Pipeline**: TopBar button to execute the rules engine (`/api/detection/run`) with live feedback.

### 2. Transactions Ledger (`/transactions`)
* **Search & Filters**: Real-time search by Transaction ID, Account Reference, or Counterparty.
* **Multi-Filter Parameters**: Filter by Risk Severity (`CRITICAL`, `HIGH`, `MEDIUM`, `LOW`), Status (`SUCCESS`, `FAILED`, `PENDING`), and Clearing Channel (`UPI`, `IMPS`, `NEFT`, `RTGS`, `CARD`).
* **Dynamic Sorting**: Sort by Newest, Oldest, Highest Amount, Lowest Amount, or Risk Score.
* **Client-Side Pagination**: Configurable rows per page (10, 25, 50) with previous/next page navigation.
* **Transaction Simulation Modal**: Injects synthetic test transactions into the pipeline with custom amounts and channels.

### 3. Transaction Forensic Deep Dive (`/transactions/[id]`)
* **Forensic Header**: Formatted amount display, transaction status, clearing rails, and composite risk gauge.
* **Transacting Counterparties**: Originating account metadata (KYC status, account tier) alongside beneficiary classifications (New Recipient vs. Known Recipient).
* **Payment Rails & Gateway Details**: Reference ID, payment channel, execution status, and timestamp.
* **Risk Evaluation Card (`RiskBreakdownCard.jsx`)**: Circular 0–100 SVG risk gauge, explanation diagnosis, and point contributions for each broken rule (e.g. `HIGH_AMOUNT_DEVIATION`, `NEW_BENEFICIARY`, `RAPID_VELOCITY`).
* **Audit Lifecycle Timeline (`TransactionTimeline.jsx`)**: Step-by-step trail from initiation and 2FA verification to heuristic evaluation and alert dispatch.
* **Reviewer Actions**: Direct actions to *Mark as False Positive* or *Open Investigation Case*.

### 4. Fully Mobile Responsive
* **Adaptive Drawer & Header**: On screens `< 768px`, the sidebar automatically transforms into a slide-out drawer accessible via an accessible hamburger toggle in the sticky mobile header.
* **Touch-Friendly Controls**: Minimum 44px tap targets, horizontally scrollable data tables (`-webkit-overflow-scrolling: touch`), responsive grid stacking, and full-screen optimized modals.
* **Zero UI Breakage**: Tested across mobile (375px–480px), tablet (768px–1024px), and desktop viewports.

## Reusable UI Primitives (`frontend/components/ui/`)

These primitives are available for reuse across the entire application, including the Alerts and Cases routes:

* **`StatCard.jsx`**: Metric card supporting formatted values, title, subtitle, trend percentages (+/–), and custom icons.
* **`StatusBadge.jsx`**: Standardized badges for transaction statuses (`SUCCESS`, `FAILED`, `PENDING`), alert priorities (`CRITICAL`, `HIGH`, `MEDIUM`, `LOW`), and case states.
* **`DataTable.jsx`**: Reusable data table with custom column renderers, empty state placeholders, loading skeletons, and row click navigation.
* **`FilterBar.jsx`**: Composable search input, dropdown filter slots, clear/reset button, and counter badges.
* **`Modal.jsx`**: Accessible dialog overlay with backdrop blur, Escape key dismissal, and custom action footers.
* **`RiskGauge.jsx`**: Dynamic SVG circular gauge with color-coded risk tiers (<40 Green, 40–69 Amber, 70–84 Orange, 85+ Red).

## Getting Started

### 1. Prerequisites
* **Node.js**: v20+ or v24+ LTS
* **Python**: 3.11+ / 3.12+ (for FastAPI backend)
* **PostgreSQL**: 16+ / 17+ / 18+

---

### 2. Frontend Setup

1. Open a terminal in the `frontend` directory:
   ```bash
   cd frontend
   ```
2. Install dependencies:
   ```bash
   npm install
   ```
3. Start the Next.js development server:
   ```bash
   npm run dev
   ```
   *(If port 3000 is occupied by another process, Next.js will automatically run on port 3001, or pass `npx next dev -p 3001`)*
4. Open your browser:
   * **[http://localhost:3000](http://localhost:3000)** (or `http://localhost:3001`)

> **Offline Fallback Note**: The frontend includes built-in mock datasets in `frontend/lib/api.js`. If the FastAPI backend is not running, the dashboard, ledger, and detail pages will automatically operate in offline demonstration mode without throwing runtime errors.

---

### 3. Backend Setup (Optional for Full Integration)

1. Open a separate terminal in the `backend` directory:
   ```bash
   cd backend
   python -m venv .venv
   
   # Windows PowerShell:
   .venv\Scripts\Activate.ps1
   # macOS/Linux:
   source .venv/bin/activate
   
   pip install -r requirements.txt
   cp .env.example .env
   # Configure DATABASE_URL in .env with your local PostgreSQL credentials
   
   alembic upgrade head
   python seed.py
   uvicorn app.main:app --reload
   ```
2. Backend API Docs: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)

## Testing & Walkthrough

1. **Dashboard Overview (`/`)**:
   * Inspect the 4 KPI cards and 7-day activity graph.
   * Click **Run Detection** in the top-right header to trigger the detection pipeline.
2. **Transactions Ledger (`/transactions`)**:
   * Type in the search bar (e.g. `SAMPLE` or `PAYEE`) to see live search filtering.
   * Filter by risk level (select `Critical (85+)`) to isolate high-risk anomalies.
   * Click **+ Simulate Transaction** to record a new synthetic payment.
3. **Transaction Details (`/transactions/[id]`)**:
   * Click **View →** on any transaction row.
   * Inspect the circular risk gauge, the individual points breakdown for each broken rule, and the lifecycle timeline.
   * Click **Flag as False Positive** or **Open Case** to test analyst triage actions.
4. **Mobile Responsiveness**:
   * Open Chrome DevTools (`F12`), toggle device toolbar (`Ctrl+Shift+M`), and test viewports such as iPhone 14 (390px) or Pixel 7 (412px).
   * Verify the hamburger menu smoothly reveals the navigation drawer and that all tables scroll horizontally without breaking page width.

## Git Workflow: Submitting Your Pull Request

To ensure your code does not touch `main` directly and is ready for team review:

```bash
# 1. Switch to your feature branch (already created):
git checkout feature/frontend-dashboard-transactions

# 2. Add your remote (if not already set):
git remote -v

# 3. Push your feature branch to GitHub/remote:
git push -u origin feature/frontend-dashboard-transactions

# 4. Open GitHub and create a Pull Request:
# Base: main <- Compare: feature/frontend-dashboard-transactions
```

### Pull Request Summary Template
* **Title**: `feat(frontend): responsive dashboard, transaction module & shared UI primitives`
* **Scope**: Developer 1 (Base layout shell, Dashboard `/`, Transactions `/transactions`, Transaction Details `/transactions/[id]`, and shared UI primitives).
* **Untouched**: `frontend/app/alerts/` and `frontend/app/cases/` remain completely untouched for Developer 2.
